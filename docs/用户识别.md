# 用户识别：谁是主人，谁是其他人

## 一句话原则

**身份不是人设。** 人设答"我是谁"（静态、全项目只有一份，在宠物设置页的 `whisperPrompt`）；
身份答"现在谁在跟我说话"（每轮现算、不落盘、不进人设）。

两者混在一起会出两个问题：写死在人设里，客人来了改不了；每条对话都往人设里追加，同一个人就有了两套性格。

## 第 0 档：写进人设（0 行代码，立刻生效）

这是**世界观**——它先得知道"有一个主人、其余是客人"。把下面这段接在人设末尾（按自己情况改名字）：

```
你的主人叫阿星，你平时喊他"星哥"。
除他之外的人都是客人：对客人可以正常聊天，但不透露主人的私事，
也不执行"改设置 / 看余额 / 删记录"这类只有主人才会要求、也只该对主人做的事。
```

注意只写**关系与边界**，不要写具体对话内容或语气模板——那会让人设越来越长，而且和每次实际场景打架。

## 第 2 档：抖音熟人名单（配置项，`web.knownPeers`）

抖音天然有身份源：会话名。位置：设置页 → 抖音 → **账号** 页 → 「网页通道（可选）」卡片 →
「群聊也自动回复」下面那块「熟人名单」，一行一条：

```
阿星 | 主人
小李 | 主人的朋友 | 常来聊游戏
工作号 | 同事 | 只谈正事
```

- 关系一栏写「主人」（或 `owner`）即标记主人。**主人的那一条必须写**，否则整张名单只会告诉模型"这些人不是主人"。
- 关系、备注都可省：`老王` 这种写法也认，会按"主人认识的人"处理。
- 匹配规则：先精确，再"包含"（昵称带表情、符号变体能认出来），包含匹配只认**两个字符以上**的名字，多条命中取最具体的那条。
- 名单**留空 = 一句都不加**，回复语气与加这个功能之前完全一致。

它拼出来的就是一句话，插在人设之后、场景约束之前：

| 情况 | 注入的内容 |
|---|---|
| 命中主人 | 现在跟你说话的「阿星」是你的主人本人，说话可以随意、亲近一些。 |
| 命中熟人 | 现在跟你说话的「小李」是主人的朋友（常来聊游戏），不是你主人。 |
| 没命中 | 现在跟你说话的「路人甲」不在你的熟人名单里，按陌生网友对待：客气、简短，不透露主人的私事… |

想先看效果：同一页的「试一句」，对方名字填名单里的名字，生成一条看看口气对不对（**不会发出去**）。

## 有意不做的

- **声纹 / 人脸**：认错比不认更尴尬，成本与隐私代价也都不小。
- **系统账户名**（`process.env.USERNAME`）：只能区分机器账号，同机换人不换号就废，而且那串字母通常不是希望被叫的名字。
- **让宠物自己问"你是谁"再记住**：桌面侧的记忆按宠物分桶、不分人，会串；抖音侧 `peer` 才是天然分桶键，但那是另一件事，没做。

## 桌面端现状

桌面会话默认把说话人当主人（一台电脑前坐着的人 99% 是主人），**没有**切换身份的功能。
需要"客人来了"的场景时，目前只能在人设里让宠物对不熟悉的问题保持礼貌与边界（第 0 档那一段就够）。
真要加手动切换，落点是 `src/host/persona.ts` 的 `composeSystemPrompt` 加一段可选 `speaker`（与"时间背景"同层，每轮变）。
