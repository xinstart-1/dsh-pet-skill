## 三、真跑才暴露的 4 个问题（已修）

### 1. 启动竞态：插件比 dsh-pet 先 apply，第一次注册必然 404

- 现象：启动日志里 `右键菜单注册失败：404`，看起来像装坏了。
- 原因：三个插件都 `inject: ['webServer']`，apply 顺序不保证 dsh-pet 的路由已挂好；本插件注册在它前面就吃 404。
- 修复：注册失败分级——前 2 次只记 **info**「暂未挂上，轮询会继续重试」，第 3 次才 warn；轮询循环里失败会自动重挂（退避 1s→3s→10s→30s）。
- 证据：修复后启动日志为 `右键菜单暂未挂上（404），轮询会继续重试` → 14 秒后 `link.petMenu: true`。

### 2. 把错误信息当成了宠物 id，污染审计 99 条

- 现象：审计里出现 `pet: "这个 owner 没有注册，重新注册即可"`。
- 原因：早期轮询直接 `Object.entries(r.data)`；而 dsh-pet 在 owner 未注册时返回 `{ok:false, reason, message}`，`message` 是字符串 → 被当成 petId → 触发一次假「浏览」→ 写审计。
- 修复：加严格解析 `parseMenuEvents`——只认 `{ok:true, events:{label: petId|null}}`，label 必须在白名单里，petId 必须是非空短字符串（≤64），`ok:false` 一律当失败。
- 附带：清掉了历史遗留的 99 条假审计。

### 3. 取 token 的失败不进审计 → 点了完全没反应

- 现象：授牌后点「看我最新作品」，审计里什么都没有、气泡也不弹（桌宠没在线时气泡本来就发不出去）。
- 原因：`ensureToken()` 写在 `try` **外面**，它抛的「还没有绑定抖音账号」直接冒泡到菜单处理层，而那一层只 `say()`（气泡不可用时等于静默）。
- 修复：把取 token 移进 `try`（失败也进审计），并在菜单各分支补 `log.warn`。
- 证据：现在审计是 `browse｜False｜还没有绑定抖音账号（设置页 → 账号 → 扫码授权）`，日志同时有一行 WARN。

### 4. dsh-pet 0.3.8 的 `/menu/events` 真实形状与 API.md 示例不一致

- 实测：`{"ok":true,"events":{"抖音：看我最新作品":null,"…":null}}`；owner 未注册时 `{"ok":false,"reason":"unknown-owner","message":"…"}`。
- 处理：解析器以**实测形状**为准，同时兼容 `ok:false` 与纯文本 404（路由未挂时）三种返回。
- 提醒：dsh-pet 的 API.md 里写的是扁平映射，文档与实现有出入，按实现来。

## 五、关于"后期联动或直接集成在一起"

先说结论：**现在已经是"联动"，不建议做成"合并"。**

**已有的联动（零代码依赖）**：两个插件都只通过 dsh-pet 的 HTTP 通道说话——`/menu/item` 注册右键项、`/menu/events` 收点击、`/broadcast` 说话、`/work-status` 写状态。dsh-pet 升级、甚至没装，两个插件都照常工作（只是没有宠物说话）。

**再紧一档的联动**（低成本，值得做）：

1. **宠物状态进设置页**：把 `/state` 里的 `petMenu`、宠物 id 列表、当前气泡显示在设置页顶部，用户一眼看到"宠物在不在、联动通不通"。
2. **能力状态回流给宠物**：账号插件每完成一次授牌/撤销，让桌宠说一句「main 现在能看我的作品了，每天 2 次」——授权行为本身有反馈。
3. **共享记忆**：dsh-pet 有 `memory.json`（对话记忆）。让账号插件的"看过什么"写进同一份记忆，宠物聊起来才有上下文。

**真要做"集成成一个插件"**，代价是明确的：

- 一个 patch entry、一个设置页、一份配置 → 安装更简单；
- 但两个能力域（发布包 = 本地文件管线；账号 = OAuth + 授牌）会耦合：任何一个的 bug 都拖死另一个，用户也不能只装一半；
- 现在这种"两个独立包 + 共享一份 pet-bridge 约定"的形态，反而更接近 dsh-pet 官方推荐的第三方扩展方式（`petE` 就是这么组织的）。

**建议路径**：保持两个独立包，抽一个共享的 `dsh-pet-client`（只是 pet-bridge 那 300 行 + 协议常量），两边都依赖它。这样协议只维护一份，等于"逻辑上集成、物理上解耦"。

# 追加：合并成一个插件（2026-10-27 22:5x）

## 决策

用户澄清原始意图是「**给 pet 一个新账号，它能全权控制，但我设置权限**」，确认"按理只需要一个插件"。于是把两个包合并为 `dsh-pet-douyin`，"发布包"降级为**第四项权限** `publish`。

1. `dsh-pet-douyin-account/` 里的 `grants.json` / `audit.json` / `usage.json` / `accounts.json` 复制到新目录（已存在不覆盖）；
