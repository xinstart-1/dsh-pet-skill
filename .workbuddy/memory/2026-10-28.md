## 00:00-00:40 人设实测：发现并修掉一个真 bug（人设从来没进过模型）

用户"已经调整了人设，检测是否正常"。检测结果分两半：

1. **配置侧正常**：人设写在**实例级** `pets[0].whisperPrompt`（486 字鲸鱼娘），
   `GET /persona?pet=main` 返回正确（人设 + 「你的名字是蓝毛小女仆」+ 时间背景）。
   条目级那份（78 字女仆短版）只对没写实例人设的宠物生效。
2. **链路侧是坏的**：抖音 `reply-preview` 空跑，问"你叫什么/今天星期几"→ 它自称
   "商量 SensenNova 模型"、说今天是星期二（实际星期四）。往 `web.replyPersona` 塞
   「必须以【XYZ】开头」也不出现 → **system 根本没进模型**。
   同样的方法验宠物对话（`POST /chat?pet=main&surface=web`）→ 也没有标记。
   **结论：宿主 `ctx.llm.stream({ system })` 的顶层 `system` 字段不生效**，人设从来没生效过
   （碎碎念/日常对话/抖音回复三条都中招）。
3. **修法**：人设改成 **system 消息**放进 `messages`（`createSystemMessage` 形状
   `{role:'system',content:[{type:'text',text}],source:{kind:'system-prompt'}}`）。
   三处：`src/host/chat.ts`、`src/host/whisper.ts`、`src/douyin/llm.js`；
   `src/standalone/shims/dsh-llm.ts` 补 `createSystemMessage`（否则构建 MISSING_EXPORT）；
   `src/douyin/llm.test.js` 的消息形状断言同步更新。
   **实测通过**：无头实例上两条链路都吐出了【XYZ】标记（宠物对话 + 抖音回复）。
   `npm run test:all` 1531(TS) + 118(抖音) 全绿、typecheck 干净。
4. 现场已还原：抖音 `web.replyPersona` 清空、autoReply/allowAutoSend/autoWake 还原 true、
   宠物人设还原 486 字（与备份逐字一致）、memory.json 还原。
